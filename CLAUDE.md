# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Axiomaths is a Next.js (App Router) site publishing math exercises, past exams, and reference material for Tunisian collège/lycée students. Nearly all "content" lives as Markdown/YAML files under version control (`exercises/`, `blog/`, `mathematicians/`, `public/exams/`) rather than in a database — the app is essentially a file-based CMS rendered through Next.js.

## Commands

```bash
npm run dev      # start dev server (http://localhost:3000)
npm run build    # production build
npm run start    # serve production build
npm run lint     # eslint (flat config, eslint-config-next)
```

There is no test suite. Content correctness is checked with the Python scripts below, not with `npm test`.

```bash
python validate_exercises.py ./exercises              # validate frontmatter/chapters against canonical lists
python validate_exercises.py ./exercises --strict      # treat warnings as errors
python validate_exercises.py ./exercises --no-solution-ok
python create_exercise.py                              # interactive prompt to scaffold a new exercise .md with next UID
python add_school_type.py [--apply] [--verbose]         # dry-run by default; injects schoolType from `source` keywords
python fix_exercises.py                                 # bulk-fix pass over exercises/ (check the script before running; it mutates files)
```

## Content model (the core architecture)

**Exercises** (`exercises/*.md`): YAML frontmatter + Markdown body. The body is split on a `## Solution` heading — everything before it is the exercise statement, everything after is the solution (see `src/lib/exerciseParser.ts`). Math is LaTeX rendered via `remark-math`/`rehype-katex`.

Frontmatter fields (`src/types/exercise.ts`, `Exercise`/`ExerciseMetadata`):
- `school`: `"college"` or `"lycee"`
- `level`: `"7eme"|"8eme"|"9eme"` (collège) or `"1ere"|"2eme"|"3eme"|"4eme"` (lycée)
- `section` / `sections`: lycée only (e.g. `"Mathématiques"`, `"Sciences Expérimentales"`); collège has none. Both a legacy single `section` and a newer `sections` array are supported for backward compatibility — always populate/read both via the parser, don't assume one is authoritative.
- `chapter`: must match the canonical chapter name for that `(school, level, section)` triple — see `CANONICAL_CHAPTERS` in `validate_exercises.py`, which is the source of truth for valid chapter names (collège chapters are in Arabic, lycée in French). `CHAPTER_ALIASES` in the same file maps common near-miss names to the canonical one.
- `professor`: array of strings (comma-separated string is also accepted and normalized).
- `schoolType`: e.g. `"pilote"`, set by `add_school_type.py` based on keywords in `source`.
- `difficulty`: `"Facile"|"Moyen"|"Difficile"`.

Filenames follow `{uid}-{school}-{level}[-{section}]-{chapter-slug}-{7-digit-uid}.md`, generated by `create_exercise.py`. Note the numeric prefix and the `uid` inside the frontmatter are tracked separately and can drift — don't assume they match.

**Frontmatter parsing is hand-rolled**, not `gray-matter` (despite it being a dependency) — see `parseFrontmatter()` in `src/lib/exerciseParser.ts`. It only handles flat `key: value`, quoted strings, and single-line `[a, b]` arrays. When adding new frontmatter fields, keep values on one line and quote strings containing `:` or special characters, or the parser will silently misparse them.

**Exams** (`public/exams/*.yaml` + matching `.pdf`): parsed with real YAML (`js-yaml`) in `src/lib/exams.ts` (`Exam` type). Filter option lists (levels, sections, exam types, years) are hardcoded in `getExamFilterOptions()` — new sections/levels must be added there manually, they aren't inferred from the data.

**Blog** (`blog/*.md`) and **mathematicians** (`mathematicians/*.md`) follow the same frontmatter + Markdown pattern via `src/lib/blogReader.ts` / `mathematicianReader.ts`.

All content readers (`src/lib/fileReader.ts`, `exams.ts`, `blogReader.ts`, `mathematicianReader.ts`) read straight off disk with Node's `fs` at request time — they're only usable in server components / route handlers, never client components.

## Routing structure

Content pages are organized as nested dynamic segments mirroring the school hierarchy:
- `/college/[level]/[chapter]`
- `/lycee/[level]/[section]/[chapter]`

Page components filter the full exercise list in-memory (`getAllExercises()` then `.filter()`) rather than querying by path — there's no per-chapter file lookup. Matching between URL segments and frontmatter values is done via a local `normalize()` helper (lowercase, strip accents, in some places strip non-alphanumerics) because French/Arabic chapter and section names vary in accents/casing between files. When adding a new filter or route, reuse this normalize-then-compare approach rather than exact string equality.

`/api/exercises` (`src/app/api/exercises/route.ts`) exposes the full parsed exercise list as JSON, used by client-side search/table components (`SearchTable.tsx`, `ExerciseTableView.tsx`, `DevoirsSearchTable.tsx`).

## Theming

Theming is two independent systems, don't confuse them:
- `src/context/ThemeContext.tsx` — light/dark mode, toggled client-side, persisted to `localStorage`, applied via a `dark` class on `<html>`.
- `src/config/themes.ts` — a palette of named color schemes (Orange/Teal, Vercel, Linear, Stripe, GitHub, Notion, Tailwind). Only one is active at a time via the `ACTIVE_THEME` export at the bottom of the file — switch schemes by changing that line, not by adding new state.

## Conventions worth knowing

- UI copy and exercise/exam content is French (lycée) or Arabic (collège); Arabic text needs `dir="auto"`/RTL-aware layout, already handled in most list/detail views — follow the existing pattern (see `ChapterPage` in `src/app/lycee/[level]/[section]/[chapter]/page.tsx`) rather than hardcoding `dir="ltr"`.
- Several files under `src/` have `.backup` siblings (e.g. `layout.tsx.backup`, `page.tsx.backup`, `tailwind.config.js.backup`) left over from prior edits — these are not imported anywhere; don't edit them expecting them to take effect, and don't treat their presence as intentional dual-maintenance.
- Path alias `@/*` maps to `src/*` (see `tsconfig.json`).
